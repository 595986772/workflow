# A. 总体判定

## A.1 结论与评分

**当前前四章已经达到“可以继续撰写第五章，并可组装完整投稿初稿”的水平，但还没有达到“可直接提交 IEEE Transactions”的水平。综合评分：7.2/10。**

当前核心故事已经基本成立，但三个关键闭环尚未完全完成：

1. 引言中的正式结果、方法名称和训练协议仍有历史残留；
2. 第三、第四章把静态解析时间戳模拟写成了严格事件驱动因果执行，强于源码事实；
3. 论文把“固定总预算下的容量空间异构”作为中心问题，但现有正式十 seed 证据仍主要集中于一个容量向量。

修复这些问题后，前四章可以形成较清晰的闭环：

\[
\text{问题设定}
\rightarrow
\text{局部缓存缺口}
\rightarrow
\text{DCC}
\rightarrow
\text{扁平动作缺口}
\rightarrow
\text{Pairwise PD3QN}
\rightarrow
\text{受控实验验证}
\]

# B. DAOC 结构拆解

## B.1 DAOC 各部分的论证功能

| DAOC部分 | 在DAOC中承担的论证功能 | OUR可以借鉴的组织方法 | OUR必须改写的技术内容 | OUR绝不能照搬的系统假设或结论 |
|---|---|---|---|---|
| 摘要 | 一段内完成场景、耦合问题、分布式缺口、方法和总体结果 | 保持“问题—缺口—方法—证据—边界”的结构 | 将分布式动机改为固定总预算下的副本协调；将普通DQN改为Pairwise PD3QN | 完全分布式、低通信自然成立、动态适应性已验证 |
| 引言 | 用实际DAG场景解释服务和依赖耦合，再提出控制缺口，最后给贡献 | 先给具体矛盾，再引出算法 | 将“中央控制不可行”改为“局部独立缓存不能管理全网副本冗余” | 把OUR写成DAOC的分布式延伸；照搬其系统应用动机 |
| 相关工作 | 通过分类和定位表收束为单一缺口 | 分类后只保留一个精确缺口，用表格说明最近工作 | 改为DAG、缓存协调、容量空间异构、动作关系建模、信息边界 | 现有方法都集中式或都假设同容量等绝对结论 |
| 系统模型 | 按任务、网络、通信和计算逐层建立完成时间 | 每个公式后解释物理意义，符号前置 | 加入固定总预算、异构容量、远程副本、多出口makespan和混合架构 | 单出口最终任务代表应用完成的假设 |
| 问题公式 | 用缓存和卸载变量形成联合问题并说明难解 | 目标—约束—组合困难的节奏 | 定义因果策略，而非预知全部未来任务的一次性离线优化 | 暗示OUR使用未来工作负载或得到全局联合最优 |
| 算法 | 分别介绍缓存、卸载、复杂度、扩展性和收敛 | 两个决策器各自形成“输入—价值—算法—复杂度”单元 | 本地EMA缓存改成DCC；Flat DQN改成Pairwise PD3QN；终端奖励改成完成前沿增量奖励 | 独立缓存、反向终端回报、完全分布式扩展性结论 |
| 实验 | 依次展示收敛、消融、机制解释和敏感性 | 每张图只回答一个研究问题 | OUR必须先区分P6/P7/P8和P9，并采用因素控制和同接口强基线 | 将不同协议、训练尾部和冻结结果混成同一统计口径 |

## B.2 OUR 应真正模仿的写作纪律

1. 每个系统量先解释物理意义，再给公式；
2. 缓存和卸载分别形成完整算法单元；
3. 状态、动作、奖励逐项定义，不让网络结构替代MDP定义；
4. 每个方法贡献都有直接对应的实验；
5. 复杂度结论与实际控制架构一致；
6. 主结果、受控比较、机制消融和敏感性分别回答不同问题。

### 推荐的DCC接受规则

\[
X_{k+1}=
\begin{cases}
\widetilde X_k,
&
\operatorname{Cov}(\widetilde X_k)>
\operatorname{Cov}(X_k),\\[1mm]
\widetilde X_k,
&
\widehat N_k
\big[J(\widetilde X_k)-J(X_k)\big]
>
\eta_{\mathrm{hys}}C_{\mathrm{mig}}(X_k,\widetilde X_k),\\[1mm]
X_k,
&
\text{otherwise}.
\end{cases}
\]

需补充：所有候选布局均已满足容量约束和驻留锁定；第一分支体现当前实现的覆盖优先接受。

## F.2 Pairwise PD3QN核验

| 核验项 | 状态 | 核验结论 | 修改要求 |
|---|---|---|---|
| 任务编码 | 一致 | 包含任务连续量、当前服务one-hot、后继服务multi-hot和结构关键度 | 状态表中不要把前驱位置算进任务编码 |
| 服务器编码 | 一致 | 每台服务器包含缓存行、前驱位置、历史质量和当前服务命中 | 明确共享同一编码器参数 |
| 注意力 | 一致但术语需修正 | 单头缩放点积cross-attention | 不写Multi-head Transformer |
| Pairwise关系 | 一致 | 任务上下文和单台服务器嵌入形成pair表示 | 不声称图神经网络或复杂关系推理 |
| Dueling | 一致 | 状态价值来自任务上下文，优势来自每个pair | 可保留公式 |
| Double-Q | 一致 | 在线网络选动作，目标网络评估 | 明确是Double DQN，不是双critic |
| 3-step return | 一致 | 单个用户DAG轨迹完成后构造n-step转移 | 区分单DAG轨迹和系统episode |
| 经验回放 | 需最终配置核对 | 代码支持更多功能，但正式文本称均匀回放且未用额外标签 | 确认正式配置关闭未使用功能 |
| 参数量 | 有材料支持 | 10个本地代理合计约405,140参数 | 明确是总量，不是单模型参数 |
| 关系信息完整性 | 有限 | 未显式输入候选链路速率、精确前驱数据量、远程加载代价或实时队列 | 可写relation-aware，但不能称完整建模所有执行成本 |

## F.3 多出口DAG的done和完成时间语义

终止条件：

\[
|\mathcal D_m|=|V_m|
\]

且每个真实任务恰好完成一次。

应用完成时间：

\[
F_m^{\mathrm{app}}
=
\max_{i\in V_m^{\mathrm{out}}}F_{m,i}.
\]

必须区分：

1. **终止条件**：所有真实任务完成；
2. **目标量**：所有出口任务完成时刻的最大值。

不能写成“最后编号任务完成即应用结束”。

## F.4 因果完成前沿奖励

定义：

\[
\Phi_{m,t}
=
\frac{
\max_{i\in\mathcal D_{m,t}}
(F_{m,i}-A_m)
}{\zeta},
\qquad
r_{m,t}=\Phi_{m,t-1}-\Phi_{m,t}.
\]

若满足：

- \(\Phi_{m,0}=0\)；
- \(\gamma=1\)；
- 每个真实任务只加入完成集合一次；
- 终止时完成集合包含全部真实任务；
- 每个非出口任务都能到达至少一个出口；

则：

\[
\sum_{t=1}^{N_m}r_{m,t}
=
-\Phi_{m,N_m}
=
-\frac{T_m}{\zeta}.
\]

### 核验结论

- 代数上的望远镜求和：**成立**；
- 严格物理时间因果：**当前静态实现尚不能完全确认**。

优先修复方案：

```text
ready
→ dispatch
→ running
→ earliest completion event
→ history/reward update
→ unlock successors
```

若不修改实现，则应把“causal observed completion frontier”收缩为：

> analytical completion frontier generated from previously assigned tasks

并停止声称历史遥测严格按真实物理完成顺序更新。

# J. 最终架构判断

最稳健的论文论证不应是：

> HERO-DAG由注意力、Dueling、Double-Q、历史遥测、关键路径缓存、滞回和多步回报等大量模块组成，因此更先进。

而应收束为：

\[
\boxed{
\begin{aligned}
&\text{固定总预算下的容量空间异构}\\
&\quad\Downarrow\\
&\text{局部独立缓存无法协调跨服务器副本}\\
&\quad\Rightarrow\quad \text{DCC}\\
&\text{Flat Q无法显式表达任务—服务器匹配}\\
&\quad\Rightarrow\quad \text{Pairwise PD3QN}\\
&\quad\Downarrow\\
&\text{通过同缓存接口、同卸载器和2×2受控实验分别验证}
\end{aligned}
}
\]

最终必须坚持以下边界：

- DCC的实证核心是全网副本协调、服务覆盖、远程加载和迁移稳定性，不是未显著的依赖权重；
- Pairwise PD3QN的实证核心是成对动作价值架构整体，不是attention、Dueling或Double-Q分别构成独立创新；
- 因果完成前沿奖励是重要的目标对齐设计，但必须先修正或限定静态执行事件语义；
- DAOC是最直接的学习型对照和写作节奏样板，但不是OUR的系统架构模板；
- 第五章应以协议注册、受控比较和证据边界为主线，而不是继续叠加未经实验的新模块。

**最终判断：**

完成“事件语义、正式结果段、DCC伪代码、命名注册和异构度证据”五项修改后，前四章可从当前的“方法较完整但存在事实口径风险”，提升到IEEE Transactions投稿初稿应具备的“定义—算法—实验可一一追溯”的状态。
